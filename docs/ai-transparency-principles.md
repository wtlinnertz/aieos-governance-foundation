# AI Transparency Principles

Version: v1.0

## Scope

This document defines organizational policy for AI transparency within the AIEOS framework. It governs how AI-generated outputs are identified and how AI systems represent the basis of their outputs.

This file applies to **all kits** — it is cross-cutting input material referenced by generation prompts and validators across the framework. It does not cover product-specific AI ethics (e.g., chatbot design, recommendation systems), which belong in kit-level principles files scoped to the relevant domain.

---

## 1. AI-Generated Output Identification

### Provenance must be traceable

Every artifact produced through AI generation must be identifiable as AI-generated. The governance model provides structural traceability (separate generation and validation sessions, human freeze points, engagement records), but the artifact itself must not obscure its origin.

### Artifacts must not present AI output as human-authored

When an artifact is generated by an AI prompt, the generation method must be discoverable. An artifact that appears to be the product of unaided human analysis, when it was in fact AI-generated, misrepresents its provenance. The mechanism for identification (metadata, header field, engagement record entry) is implementation-specific, but the capability must exist.

### Human modifications do not erase AI origin

An AI-generated artifact that is subsequently edited by a human is a human-reviewed AI artifact, not a human-authored artifact. The original generation method remains part of the artifact's provenance.

---

## 2. AI Output Integrity

### AI must not present inferred information as established fact

When an AI generation prompt produces output that fills gaps not present in the input material, those inferences must be marked explicitly. Information marked as "Known" must have a traceable basis in the input artifacts. Information without such basis must be marked as "Assumed" or "Inferred."

This rule operationalizes the existing "no inferred information — mark it explicitly" instruction that appears across kit operating rules.

### AI must not fabricate evidence or sources

AI-generated artifacts must not cite sources, data, metrics, or prior decisions that do not exist in the provided input material. A citation that cannot be traced to an actual input artifact is a fabrication, regardless of whether it is plausible.

### Confidence boundaries must be stated

When an AI generation prompt produces analysis, risk assessments, or recommendations, the output must distinguish between conclusions supported by the input material and extrapolations beyond it. An analysis that presents extrapolation with the same confidence as grounded conclusions misrepresents its reliability.

## Enforcement Mapping

| Rule Category | Enforced By | Status |
|---------------|-------------|--------|
| Provenance traceability (§1.1) | Engagement record spec (`engagement-record-spec.md`) — artifact IDs and generation method tracked per layer | **Active** |
| AI output not presented as human-authored (§1.2) | Advisory — no current hard gate. Structurally supported by the governance model's session separation and freeze protocol. | **Advisory** |
| Human modifications do not erase AI origin (§1.3) | Advisory — reinforced by engagement record entries but no hard gate validates this property. | **Advisory** |
| No inferred information presented as fact (§2.1) | Enforced per-kit: validator hard gates for `information_basis` or equivalent in PIK (`problem-framing-validator.md`), EEK (`prd-validator.md`, `sad-validator.md`), and downstream kits. | **Active (per-kit)** |
| No fabricated evidence or sources (§2.2) | Enforced per-kit: validator hard gates for source traceability (e.g., EEK `sad-validator.md` §intent_integrity, `tdd-validator.md` §traceability). | **Active (per-kit)** |
| Confidence boundaries stated (§2.3) | Advisory — no current hard gate. Reinforced by generation prompts that distinguish Known/Believed/Assumed (PIK `product-discovery-principles.md` §8). | **Advisory** |

Rules marked **Advisory** are not currently enforced by a hard gate in any spec. They represent organizational policy that generation prompts should respect. Promotion to **Active** requires adding corresponding hard gates to the relevant specs.
